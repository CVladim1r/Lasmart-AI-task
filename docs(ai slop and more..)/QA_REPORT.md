## Покрытые сценарии

- Вход: неизвестный email, неверный пароль, успешная авторизация, восстановление и завершение сеанса.
- Защита: закрытые endpoints, CSRF-проверки, прекращение доступа после удаления сотрудника, отсутствие пароля и хеша в ответах API.
- Валидация: обязательные поля, формат и уникальность email без учёта регистра, минимальная длина пароля, совпадение подтверждения.
- CRUD: создание, изменение профиля, смена пароля, сохранение прежнего пароля при пустом новом значении, удаление с подтверждением.
- Реестр: поиск подстроки ФИО без учёта регистра, пустой результат, сортировка по одному полю, страницы 25/50/100, корректировка последней страницы после удаления.
- Клавиатура: Tab/Shift+Tab внутри диалога, Escape, возврат фокуса и отмена.
- Адаптивность: размеры от 390 до 1440 px, длинные ФИО/email, доступность действий строки, отсутствие горизонтального переполнения. Снимки интерфейса визуально проверены.

Однократность начальной инициализации и устойчивость данных при перезапуске API/PostgreSQL проверены в отдельной тестовой БД. Изменение или удаление начального сотрудника не восстанавливает исходную учётку.

Временные записи, созданные проверками, удалены.

## Повторный запуск

Для API задайте учётные данные существующего начального сотрудника:

```sh
QA_BASE_URL=http://localhost:8080 QA_EMAIL="$SEED_EMAIL" QA_PASSWORD="$SEED_PASSWORD" python3 scripts/qa_api.py
```

Для браузерных проверок нужны Playwright Core и системный Chromium. Путь к Playwright Core можно передать через `PLAYWRIGHT_CORE_PATH`, к Chromium — через `CHROMIUM_PATH`.

```sh
npm install --prefix /tmp/vibetime-qa playwright-core
mkdir -p .impeccable/review
QA_EMAIL="$SEED_EMAIL" QA_PASSWORD="$SEED_PASSWORD" QA_UI_URL=http://localhost:8080 node scripts/qa_ui.mjs
```

Скрипты API/UI создают уникальные временные записи и удаляют собственные fixtures. Снимки браузерных проверок сохраняются в `.impeccable/review/`.
